### 进程与进程的上下文切换

- 时间片（*time slicing*）
- 上下文切换 (*Context Switching*)



**cpu**所执行的***指令的地址序列*** 称为 cpu 的控制流
- 正常控制流
- 异常控制流 (exception control of flow, ecf)
	- 形成原因：
	- 内部异常 (hardware)
	- 外部中断 (hardware)
	- 进程的上下文切换（操作系统）
	- 一个进程直接发送信号给 lingerie 进程（应用软件层）
#### 程序和进程
- **program**: 静态过程
- **process**: 程序的一个运行过程。确切的说，是一个具有独立功能的程序关于某个数据集合的一次运行活动，因此具有 **动态含义**。同一个程序处理不同的数据就是不同的进程


对于单处理器系统，进程会轮流使用 **处理器**。处理器的物理控制流，**由不同逻辑控制流交叉组成**。

- **并发**: concurrency
	- 不同进程的逻辑控制流在时间上交错或重叠的情况
- **并行**：parallelism
	- 两个逻辑流在时间上同时执行

> [!Summary] 并行和并发的关系
> 并行是并发的一种特例。并行执行的两个进程一定是并发的。显然，并行执行的两个进程必定同时使用不同的处理器或处理器核


#### 进程与上下文切换 context switching
os 通过**处理器调度**让处理器轮流执行多个进程。实现不同进程中指令交替执行的机制。称为**进程的上下文切换**。(context switching)
![image.png|400](https://kold.oss-cn-shanghai.aliyuncs.com/20251215092324.png)

**进程**的上下文切换包括哪些内容？
- **用户级上下文**
	- 用户进程的代码、用户进程数据、运行时的堆和用户栈。
- **系统级上下文**
	- 进程标识信息
	- 进程现场信息
	- 进程控制信息
	- 系统内核栈

切换是一个用户态中断到系统态处理的过程。

**内部异常**分为三类
- 故障 fault
- 陷阱 trap
- 终止 abort
#### 故障 Fault
CPU 执行指令过程中，检测到的一类与指令执行相关的意外事件。
- 有些可以恢复
- 有些不能恢复
	- 除 0 (SIGFPE) 页故障 (SIGSEGV)
	- **页故障**：
		- 如果发生地址越界、访问越权，则故障不可恢复
		- 否则
			- 检查异常的访存地址是否属于当前进程的虚拟地址空间
			- 若否，则不可恢复
			- 若属于，可恢复
	- 不可恢复的访存故障，**称为段故障**(Segmentation Fault!)


#### 陷阱 Trap
AKA **自陷、陷入**
和故障等其他异常不同，是预先安排的“异常”
**执行到陷阱**，CPU 调用相应程序进程处理，处理结束后返回到陷阱指令的下一条指令执行。

**最重要作用**：提供 ***系统调用***

陷阱也提供了**断点支持**

#### 终止 Abort
如果执行指令过程发生了严重错误，如控制器出现问题，访问DRAM 时无法纠正的校验错等，只能终止。

#### IDT 的初始化
> [!Question] 什么是IDT？
> IDT (Interrupt Descriptor Table), 中断描述符表。共有 256 项。对应上表所示的中断类型。
> IDT 的首地址记录在IDT 寄存器中
> IDT 的格式：
> - **中断门的**：
> ```
> +-----------------------------------+
> |	偏移地址(A31 ~ A16)				|
> +-----------------------------------+
> |	P	DPL	01110	000000000		|
> +-----------------------------------+
> |	偏移地址(A15 ~ A0)				|
> +-----------------------------------+
> ```
> P **字段的解释**：（Present）
> - P=1 表示段存在
> - P=0 表示段不存在
> - Linux 总是把P 置 1，因为它从不把一个段交换到外存中

#### GDT 的内容

- **回顾**：linux 分段机制

**由于**我们触发的系统调用实际都位于内核代码段，所以你知道如何做了。
`10D = 1010B`
`TYPE[0] = Access bit`

**字段内容解释**：
- **G**(**Granularity**), 粒度
- 限界，`4GB` 空间
- **S（System Segment）**：是系统可用吗
- **TYPE**：
	`| X | C/E | R/W | A |`
	- X: Executable?
	- C/E: Conforming, Expansion
	- Read/Write?
	- Access
		- 是否被CPU 使用过
	- **C/E**
		- 它们共用一个bit，但是代码段使用C 的含义，数据采用E 的含义
		- **C 位和 E 位共用 `TYPE` 字段中的同一个 bit（bit 2）**，但它们的含义取决于当前段的类型 —— 是代码段还是数据段。

| 是否允许低特权级跳转  | 是否提升特权级 | 典型用途       |               |
| ----------- | ------- | ---------- | ------------- |
| 非一致（C=0）    | ❌ 不允许   | ✅ 提升（需通过门） | 正常内核函数        |
| 一致（C=1）<br> | ✅ 允许    | ❌ 不提升      | 公共可执行代码（安全函数） |
| <br>        |         |            |               |
**显然系统代码段**的C=0. 不允许越权访问内核函数。

#### IDT 门描述符


IA-32/x86-64 提供了三种包含在IDT 中的门描述符：
- **中断门描述符**
- **陷阱门描述符**
- **任务门描述符**
构造了五种类型的门描述符

- **中断门**（interrupt gate）
	- DPL=0
	- TYPE=1110B
	- 所有Linux 中断服务程序都通过中断门激活
- **系统中断门**(system interrupt gate)
	- DPL=3
	- TYPE=1110B
	- activate no. 3 interrupt (break point) exception handler program
	- `int 3`
	- can be used in User state

- **系统门**(system gate)
	- DPL=3
	- TYPE=1111B
	- 激活三个trap 类异常 ,中断类型号 (4, 5, 128)
	- 对应 `into, bound, $0x80`
	- 由于DPL=3, so can be used in User State
- **陷阱门**(trap gate)
	- DPL=0
	- TYPE=1111B
	- 阻止使用 `INT n (n!=128 && n!=3)`
	- 这里设置 `DPL=0`，是为了触发 13 号异常 ( `#GP`, 通用保护错 )
- **任务门**(task gate)
	- DPL=0
	- TYPE=0101B
	- 8 号中断（双重故障）用任务门激活

### CPL & DPL
在**计算机体系结构**（特别是**x86 保护模式**）中，DPL 和 CPL 是与**特权等级**相关的概念：
- **CPL (Current Privilege Level)：当前特权等级**
    - 表示当前正在执行的**程序或任务**的特权等级。
    - 它存储在**代码段 (CS)** 和**栈段 (SS)** 寄存器的最低两位。
    - 等级范围是 0 到 3，**0 是最高特权（内核/操作系统）**，**3 是最低特权（用户应用）**。
- **DPL (Descriptor Privilege Level)：描述符特权等级**
    - 表示一个**段（Segment）**所允许的**最低特权等级**。
    - 它存储在**段描述符**中。
    - 例如，一个数据段的 DPL 决定了哪些特权等级的程序可以访问这个段；一个代码段的 DPL（作为调用门的一部分）决定了哪些特权等级的程序可以调用它。

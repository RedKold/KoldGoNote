### 简述 RDBMS 和 NoSQL 数据库的区别
RDBMS: **R**elational **D**atabase **M**anagement **S**ystem
**SQL**: Structured Query Language: 结构化查询语言
NoSQL: Not Only SQL
- **泛指非关系型数据库**。

二者的区别：
**RDBMS**
- 完善的关系代数理论做基础，有严格的标准，支持事务 ACID 四性，借助索引机制可以实现高效的查询
- 可拓展性差，无法较好支持海量数据存储，数据模型过于死板，无法较好支持 `Web2.0` 应用。事务机制影响了整体性能
**NoSQL**
- 可以支持超大规模数据存储，灵活的数据模型可以很好地支持**Web2.0应用**，具有强大的横向扩展能力等
- **缺乏数学理论基础**，复杂查询性能不高，大都不能实现事务强一致性，很难实现数据完整性

总结一下：
- **数据库原理上**：
	- RDBMS 完全支持（关系代数理论）
	- NoSQL：没有统一的理论
- **数据规模上**：
	- RDBMS: 大规模, 不方便拓展
	- NoSQL: 超大规模，容易拓展
- **数据库模式**：
	- RDBMS: 固定的。需要严格遵守数据定义和相关约束
	- NoSQL: 不存在数据库模式，可以自由灵活定义并存储不同类型的数据
- **查询效率**
	- RDBMS： 快
		- 借助索引机制，快速查询。
	- **NoSQL**
		- 使用 MapReduce 加速查询，但是对于复杂查询仍然不敌 RDBMS
### 简述 CAP 定理的含义
CAP 定理:
指出对于一个分布式计算系统，不可能同时满足以下三点：
- **一致性**(Consistency):
	- 任何一个读操作总是能够读到之前完成的写操作的结果。**多点的数据一致**
- **可用性**(Availability)
	- 快速获取数据，**可以在确定的时间内返回操作结果**
- **分区容忍性** (Partition tolerance)
	- 当出现网络分区的情况时（即系统中的一部分节点无法和其他节点进行通信）分离的系统也能够正常运行。
	- 系统中任意信息的丢失和失败不会影响系统的持续运作。


- **CA**：如果选择保证一致性和可用性，则在分区容忍性方面可能需要牺牲，即在网络分区发生时，系统可能会停止响应请求，并且通常扩展性较差。
- **CP**：如果选择保证一致性和分区容忍性，则可能需要牺牲可用性，即在网络分区发生时，可能会**有一些节点无法响应请求**。
- **AP**：如果选择保证可用性和分区容忍性，则可能需要牺牲一致性，即在网络分区发生时，数据可能在不同节点上具有不一致的状态。
### 简述 ACID 和 BASE 的区别
- **ACID**:
	- ACID: 原子性，一致性，隔离性，持久性
	- Atomicity, Consistency, Isolation, Durable
	- **A**: 事务是原子工作单元. 对于数据的修改要么都执行，要么都不执行
	- **C**: 事务在完成时，必须使得所有的数据保持一致状态
	- **I**： 隔离性。由并发事务所做的修改必须与其他任何并发事务所做的修改隔离
	- **D** ：一旦事务提交，对数据库的更改就是永久性的，系统发生故障也不会丢失
- **BASE**:
	- Basically Available, Soft-state, Eventually Consistent
	- 对 NoSQL 数据库通常对可用性和一致性的弱要求原则
		- **基本可用**
		- 软状态。（Soft-state: 无连接的）
		- **最终一致性**。

**二者的区别**：
- **ACID**是对 CAP 定理中的 CP 的落实，**更强调一致性**。
	- **一致性**+**分区容忍性**
	- 其在系统故障的时候，**牺牲一定的可用性**换取 CP。
- 而 **BASE** 是对 CAP 定理中的 AP 的倾向。对于一致性，其只保证**最终一致性**。**更强调基本可用性**


### 简述最终一致性的含义
**最终一致性**：是弱一致性的一种特例
- 弱一致性：不能保证后续操作访问到的都是更新后的最新数据。
- **最终一致性**允许后续的访问操作可以暂时读不到更新后的数据，但是过一段时间后，必须读到更新后的数据。
- **分类**
	- 因果一致性
		- 进程 A 通知进程 B 它已经更新了一个数据项， B 后续访问获得 A 写入的最新值。和 A 无因果关系的 C 的访问，仍然遵守一般的最终一致性
	- "读己之所写"
		- 视为因果一致性的一个特例。当进程 A 自己执行一个更新操作之后，它自己总是可以访问到更新过的值，不会看到旧值
	- **单调读一致性**：如果进程已经看到过数据对象的某个值，则后续访问都都不会访问在那个值之前的值
	- 会话一致性：store the **process** which **access** the storage system into context of **session**. If session is alive, system keep consistency.  If session is terminated, we need to set up new sessions. (它把访问存储系统的进程放到会话（session）的上下文中)
	- **单调写一致性**：系统保证来自同一个进程的写操作顺序执行。系统必须保证这种程度的**一致性。**

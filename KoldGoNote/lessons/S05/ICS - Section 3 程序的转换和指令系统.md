### 一个指令的地址字段
- **零地址指令**
	- 无需操作数
	- 所需操作数是默认的 （堆栈，累加器）
#### 零地址指令（Zero-Address Instructions）

- **工作原理**：指令中不包含任何操作数地址。所有操作数都隐含地从一个被称为**栈**（Stack）的数据结构中获取。
- **执行过程**：指令会从栈顶弹出（pop）一个或多个操作数进行运算，然后将结果压入（push）栈顶。
- **优点**：指令长度短，编码简单。
- **缺点**：需要额外的栈操作来准备操作数，程序代码可能较长。
- **例子**：`ADD`。这条指令会弹出栈顶的两个操作数，相加后将结果压回栈顶。这种设计常见于**栈式机**（Stack Machine），例如早期的虚拟机（JVM）和某些计算器。
---

#### 一地址指令（One-Address Instructions）

- **工作原理**：指令包含一个操作数地址。通常，另一个操作数隐含地存储在一个特殊的寄存器中，这个寄存器被称为**累加器**（Accumulator）。
- **执行过程**：指令会从指定的地址获取一个操作数，并将其与累加器中的值进行运算，然后将结果存回累加器。
- **优点**：指令相对简洁，比零地址指令更易于理解。
- **缺点**：所有操作都依赖于累加器，灵活性受限。
- **例子**：`ADD X`。这条指令表示将内存地址 X 处的数据与累加器中的值相加，并将结果存入累加器。这种设计在早期的计算机架构中很常见。
---

#### 二地址指令（Two-Address Instructions）

- **工作原理**：指令包含两个操作数地址。其中一个地址既是源地址，也是目的地址。
- **执行过程**：指令从两个地址获取操作数，运算后将结果存入第一个地址。
- **优点**：比一地址指令更灵活，指令更紧凑。
- **缺点**：源操作数之一会被覆盖，需要额外的指令来保存原始值（如果需要的话）。
- **例子**：`ADD R1, R2`。这条指令表示将寄存器 R1 和 R2 中的值相加，并将结果存回 R1。这种模式在大多数**精简指令集计算机（RISC）** 架构（如 ARM、MIPS）和**复杂指令集计算机（CISC）**架构（如 x86）中都非常普遍。

---

#### 三地址指令（Three-Address Instructions）
(`RISC` 风格)
- **工作原理**：指令包含三个操作数地址。两个地址作为源操作数，一个地址作为目的地址。
- **执行过程**：指令从两个源地址获取操作数，运算后将结果存入一个独立的目的地址。
- **优点**：指令明确，每个操作数都有独立的地址，不会覆盖源数据，易于编写和理解。
- **缺点**：指令长度较长，因为需要编码三个地址。
- **例子**：`ADD R3, R1, R2`。这条指令表示将寄存器 R1 和 R2 中的值相加，并将结果存入寄存器 R3。这种模式在现代 RISC 架构中很常见，因为它允许编译器生成更优化的代码。

### IA-32 定点寄存器组织
- 8 个通用寄存器 `GPRs`
	- 这些是 x86 架构中主要的 8 个 32 位通用寄存器，它们的 64 位版本通常以 `R` 开头（例如，EAX 对应 RAX），16 位版本以 `A` 开头（例如，EAX 对应 AX）。
	- **`EAX`**：**E**xtended **A**ccumulator Register（扩展累加器）。
	    - **历史用途**：主要用于算术运算的累加器。
	    - **现代用途**：在 C/C++ 等语言中，`EAX` 寄存器通常用于存放**函数调用的返回值**。
		
	- **`EBX`**：**E**xtended **B**ase Register（扩展基址寄存器）。
	    
	    - **历史用途**：通常用作内存地址的基址，用于访问数据。
	        
	    - **现代用途**：在 64 位模式下，`RBX` 通常用作**非易失性寄存器**，函数调用时需要由被调用函数保存和恢复其值。
	        
	- **`ECX`**：**E**xtended **C**ount Register（扩展计数寄存器）。
	    
	    - **历史用途**：主要用于循环和字符串操作中的计数器。
	        
	    - **现代用途**：在 `REP` 指令家族（如 `REP MOVSB`）中，`ECX` 寄存器仍然用作**循环计数器**。
	        
	- **`EDX`**：**E**xtended **D**ata Register（扩展数据寄存器）。
	    
	    - **历史用途**：在乘除法运算中，与 `EAX` 配合使用来存放 64 位结果或被除数的另一半。
	        
	    - **现代用途**：与 `EAX` 一起用于处理 64 位整数运算。在函数调用中，它有时也用于传递参数。
	        
	- **`ESP`**：**E**xtended **S**tack **P**ointer（扩展栈指针）。
	    
	    - **用途**：指向**栈顶**的地址。它负责跟踪栈的当前位置，所有 `push` 和 `pop` 操作都会隐式地修改它。`ESP` 在函数调用和返回时非常关键。
	        
	- **`EBP`**：**E**xtended **B**ase **P**ointer（扩展基址指针）。
	    
	    - **用途**：通常用于指向**栈帧的基址**。它提供了一个稳定的参考点，方便程序通过固定的偏移量来访问函数的局部变量和参数。
	        
	- **`ESI`**：**E**xtended **S**ource **I**ndex（扩展源变址寄存器）。
	    
	    - **用途**：在字符串和内存块操作中，通常用作**源数据**的地址指针。
	        
	- **`EDI`**：**E**xtended **D**estination **I**ndex（扩展目的变址寄存器）。
	    
	    - **用途**：在字符串和内存块操作中，通常用作**目的数据**的地址指针。
- 2 个 **专用寄存器**
	- `EIP`:  **E**xtended **I**nstruction **P**ointer
	- `EFLAGS`: 标志寄存器

### 寻址方式 Addressing Model
- **指令或操作数地址的指定方式**
	- 根据地址找到指令或操作数的方法

- **寻址方式的确定**
	- **没有专门的寻址方式**位 （由操作码确定）
		- `MIPS`
	- **有专门的寻址方式位**
		- `x86`
- **有效地址**
	- 操作数所在的存储单元的地址（可能是逻辑地址或物理地址），**可通过指令的寻址方式和地址码计算得到**
- **基本寻址方式**
	- 立即（立即数）
		- `$0xFFF000`
	- 直接 （读地址）
		- **指令中给出的地址码是操作数的有效地址**
		- **需要用括号括起来，否则无法解读**（从汇编来说）
	- 间接 （`*`）
		- 指令中给出的地址码是存放操作数有效地址的 **存储单元** 的地址。
		- 跟着再读一次（AT&T: `(%ebx)`）
	- 寄存器
		- 指令中给出的地址码是操作数所在的寄存器编号
		- **寄存器直接寻址**
	- 寄存器间接
		- 指令中的地址码给出了一个寄存器编号，**这个寄存器存储了** 操作数的有效地址
	- 偏移
	- 栈

### 指令的不同形式

- ![image.png|500](https://kold.oss-cn-shanghai.aliyuncs.com/20250922104133.png)
- 一个例子

```
1000fe: 66 c7 84 99 00 e0 ff ff 01 00
```

---

#### 1. 指令前缀

```
66
```

- **操作数大小覆盖前缀 (Operand-size override prefix)**。  
    在 32 位模式下：让 `mov imm32` 变成 `mov imm16`。  
    在 64 位模式下：让 `mov imm32` 变成 `mov imm16`。
    

所以这里最终是 **往内存里写 16 位数**。

---

#### 2. 主操作码

```
c7
```

- **`C7 /0` = MOV r/m16, imm16 或 MOV r/m32, imm32**  
    （因为有 66h 前缀，所以是 `mov r/m16, imm16`）。
    

---

#### 3. ModR/M 字节

```
84
```

二进制：`1000 0100`

- Mod = `10` (内存地址 = 寄存器 + disp32)
    
- Reg = `000` (对应 `MOV` 的扩展码 `/0`)
    
- R/M = `100` → 特殊：表示 SIB 字节跟随
    

---

#### 4. SIB 字节

```
99
```

二进制：`1001 1001`

- Scale = `10` (缩放因子 = 4)
    
- Index = `011` (寄存器 EBX)
    
- Base = `001` (寄存器 ECX)
    

所以地址形式 = `ECX + EBX*4 + disp32`。

---

#### 5. displacement (位移)

```
00 e0 ff ff
```

小端序 → `0xFFFFE000` (有符号数，= -0x2000)。

---

#### 6. immediate (立即数)

```
01 00
```

小端序 → `0x0001` (16 位，因为有 66 前缀)。

---

#### 7. 汇编指令最终形式

```
mov WORD PTR [ecx + ebx*4 - 0x2000], 0x1
```

---

✅ **总结**  
这条指令的意思是：  
把 **常数 1 (16 位)** 存入内存单元 `[ecx + ebx*4 - 0x2000]`。

#### 四则运算

好的，以下是 x86/x86-64 汇编中常用的四则运算指令，根据有符号和无符号操作进行的总结表格。所有指令后缀（如 `b`, `w`, `l`, `q`）取决于操作数的大小（8位、16位、32位、64位）。

| **运算类型** | **算术运算**                   | **有符号 (Signed) 指令**       | **无符号 (Unsigned) 指令** | **结果存储和特点**                                                                                                                            |
| -------- | -------------------------- | ------------------------- | --------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **加法**   | $\text{A} + \text{B}$      | `ADD`                     | `ADD`                 | 结果存储在目标操作数中。有符号溢出由 $\text{OF}$ 标志指示；无符号进位由 $\text{CF}$ 标志指示。                                                                           |
| **减法**   | $\text{A} - \text{B}$      | `SUB`                     | `SUB`                 | 结果存储在目标操作数中。有符号溢出由 $\text{OF}$ 标志指示；无符号借位由 $\text{CF}$ 标志指示。                                                                           |
| **乘法**   | $\text{A} \times \text{B}$ | `IMUL` (Integer Multiply) | `MUL` (Multiply)      | **`MUL`** 和 **`IMUL` (单操作数)** 结果为操作数宽度的**两倍**（例如 $32 \times 32 \to 64$ 位 $\text{EDX}:\text{EAX}$）。 **`IMUL` (双/三操作数)** 结果为操作数**单倍宽度**。 |
| **除法**   | $\text{A} / \text{B}$      | `IDIV` (Integer Divide)   | `DIV` (Divide)        | **被除数**必须预先进行**符号扩展**（`IDIV` 使用 `cwd`/`cdq`/`cqo`）或**零扩展**（`DIV` 清空高位寄存器）。 **商**存储在 $\text{A}$ 寄存器中，**余数**存储在 $\text{D}$ 寄存器中。         |

##### 关键点简述：

1. **加减法 (`ADD`, `SUB`)：** 这两条指令本身不区分有符号和无符号。**区别在于它们如何设置标志位**，以及程序员如何使用这些标志位进行条件跳转（例如，`JO/JNO` 用于有符号溢出，`JC/JNC` 用于无符号进位/借位）。
    
2. **乘法 (`IMUL`, `MUL`)：** 这是两条不同的指令，直接在硬件上区分了有符号和无符号乘法。
    
3. **除法 (`IDIV`, `DIV`)：** 这是两条不同的指令，直接在硬件上区分了有符号和无符号除法，并且对被除数的准备方式不同。
    

##### 寄存器使用总结（以 32 位操作为例，后缀为 `l`）：

| **指令**          | **隐含的被乘/被除数**                     | **隐含的结果/商**           | **隐含的余数/高位**          |
| --------------- | --------------------------------- | --------------------- | --------------------- |
| **`mull src`**  | $\text{EAX}$                      | $\text{EAX}$ (低 32 位) | $\text{EDX}$ (高 32 位) |
